# Real PaddleOCR-VL format check — issue #4

## Input and reproduction

This check uses only a synthetic page generated by
`scripts/check_paddle_format.py`: a document title, two numbered section headings,
body text, and the equation E = mc² with a separate number (1). No sensitive
legal-vi-ocr documents are used.

Run in a **separate Paddle environment**, not the gateway environment. Requires
local PaddleOCR-VL-1.6 and Transformers-format PP-DocLayoutV3 weights, CUDA,
Pillow, and DejaVu fonts. The script disables model downloads and source checks.
Choose a free GPU and a new output directory (the script refuses to overwrite).

From the gateway repository, the verification command was:

```sh
CUDA_VISIBLE_DEVICES=2 \
  ../legal-vi-ocr/experiments/paddleocr-vl/.venv/bin/python \
  scripts/check_paddle_format.py \
  --model ../legal-vi-ocr/models/PaddleOCR-VL-1.6 \
  --layout ../legal-vi-ocr/models/PP-DocLayoutV3_safetensors \
  --output docs/validation/paddle-format
```

Saved artifacts in [paddle-format/](paddle-format/):

- `input.png`: the actual synthetic input.
- `response.json`: Paddle's `result.json`, not the gateway response.
- `markdown.md`: Paddle's `result.markdown["markdown_texts"]`, not a local
  Markdown conversion.
- `versions.json`: package versions for this run.

The run uses PaddleOCR 3.7.0, PaddleX 3.7.2, Transformers 5.21.1,
PyTorch 2.6.0+cu124, and an NVIDIA A100. These packages and GPU requirements
are confined to the manual check; no gateway dependency was added.

## Contract decision

The real output confirms that Paddle formula `block_content` **can contain
`$$`**, and that numbered paragraph titles do not always use `##`.

The gateway intentionally retains the explicit rules in issues #1 and #4:

- Formula content goes through pinned MonkeyOCRv2 `process_formula` and is
  unwrapped LaTeX; Markdown adds `$$`.
- Document titles use `# `; paragraph titles always use `## `.
- Monkey labels map according to the specified table, including
  `Formula → formula`, not Paddle 1.6's observed `display_formula`.
- Equation numbering retains pinned Monkey behavior, not Paddle's separate
  formula-number block behavior.

This is schema/spec compatibility, not byte-for-byte Paddle rendering parity.
Changing these rules to match this Paddle version would require changing the
explicit issue contract; this verification does not silently change it.
